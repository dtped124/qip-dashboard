# 驗收手冊：上雲前的親自驗證（P1–P8）

> 對象：品管中心主管（系統擁有者）。目的：不看程式碼，用瀏覽器走一遍，確認「門擋得住、正常人不被卡死、分子分母分派可用、開啟夠快」。全程約 60–90 分鐘。
> 每一節末尾有「✅ 預期」與勾選格；不符的請記在第 9 節「問題回報」。第 7A 節（AD 登入）只在要啟用 AD 時做，另計約 20 分鐘。

## 0. 準備（10 分鐘）

### 0.1 啟動環境
在專案目錄（`C:\claude\QIP monitor\qip-dashboard`）：

```bash
docker compose up -d
```

等 `docker compose ps` 顯示 `postgres`、`redis` 為 `healthy`、`api` 為 `Up`。
前端：**先確認 3000 埠有沒有已經在跑的前端**（瀏覽器開 http://localhost:3000 看得到登入頁就是有）。沒有的話另開終端：

```bash
npm run dev
```

> 若 api 比 postgres 先起來（例如剛開機），`docker compose restart api` 一次即可。
> 若 3000 已被占用，`npm run dev` 會自動改用 3001；手冊裡的網址請自行把 3000 換掉。

### 0.2 帳號
| 帳號 | 顯示姓名 | 身分 | 用途 |
|---|---|---|---|
| `admin` | 系統管理員 | 管理員 | 建帳號、指派、匯入、看全部 |
| `demo_a` | 示範甲（分子） | 填報者＋看資料 | HA03-01 竹北 **只填分子** |
| `demo_b` | 示範乙（分母） | 填報者 | HA03-01 竹北 **只填分母** |
| `demo_r` | 示範審核者 | 審核者＋看資料 | 審核竹北 HA03 |

示範帳號密碼在 `local-data/demo-accounts.md`（不在 git 裡）。畫面上顯示的是「顯示姓名」，括號是姓名的一部分。

**admin 的密碼請先輪替**（舊的預設密碼曾在原始碼裡）。在**同一個 cmd 視窗**依序執行（第一行是 cmd 語法）：

```bat
set "SEED_ADMIN_PASSWORD=你的新密碼"
```

```bash
docker compose exec -T -e SEED_ADMIN_PASSWORD api python manage.py seed_admin --reset
```

密碼至少 10 字、含英文數字符號、**不要含 `& ^ % !`、不要含 `admin`**。之後 admin 首次登入會被要求再改一次密碼，**新密碼要跟剛設的不同**（這是設計）。

### 0.3 三件要先知道的事
- **示範資料只在 115 年 10 月**（竹北、手術照護 HA03）。填報頁一律顯示「現在的年月」，所以第 4 節請在 10 月內做；過了 10/31 會看到空白的新月份，示範數字要重填。
- **切換帳號**：同一個視窗一次只能登一個帳號。第 4 節要在 admin、示範甲、示範乙、示範審核者之間切換，建議開三個：一般視窗（admin）、無痕視窗（示範甲）、另一個瀏覽器或 Edge InPrivate（示範乙）；審核者在第 4 節最後才上場，到時用無痕視窗登出示範甲改登即可。
- 看後端回應：F12 → Network 分頁，篩 `api` 就能看到每支 API 的狀態碼與標頭。Chrome／Edge 第一次在 Console 貼程式碼可能要先輸入 `allow pasting`。

## 5. 開啟速度（5 分鐘）

| 步驟 | 動作 | ✅ 預期 | 勾 |
|---|---|---|---|
| 5-1 | admin：先開 F12 → Network，再按 F5 開儀表板，找 `dashboard/?campus=` 那筆 → Headers | 回應標頭 `X-Dashboard-Cache` 為 `MISS`（第一次）或 `HIT`。開發模式會出現兩筆，第一次都可能是 MISS | ☐ |
| 5-2 | 再按 F5 | `HIT`，Time 明顯短於第一次的 MISS | ☐ |
| 5-3 | Network 開著、先 F5 一次，再在站內點 3 個頁面（達文西 → QIP → 設定） | `/api/auth/me` **只有 F5 那 1 次**，站內換頁不再打 | ☐ |
| 5-4 | admin 開任一指標詳情頁的「挑戰平均值模式」卡 →「設定目標」（或「編輯目標」）→ 填一個數字 →「套用」；回儀表板 F5。驗完再「編輯目標」改回原值（原本沒啟用就按「停用」） | 第一次變回 `MISS`（快取已失效），之後 `HIT` | ☐ |

> 若標頭是 `BYPASS`，代表快取沒啟用（Redis 沒起來或 `REDIS_URL` 沒設），功能仍正常只是不快取。

## 7. （選做）部署試跑（30 分鐘，需 ≥15 GB 可用磁碟）

根目錄已有一份試跑用的 `.env.prodtest`（10/11 建立，鍵齊全、cookie 非 Secure、綁 127.0.0.1）；沒有的話照 `docs/DEPLOYMENT.md` §2 逐行建立，**不要只複製範本**（範本是 Secure cookie、密碼空白）。

```bash
docker compose -p qip-prodtest -f docker-compose.prod.yml --env-file .env.prodtest up -d --build
```

✅ 四個服務 healthy；**用全新的無痕視窗**開 `http://localhost:3100/entry/login`（同一瀏覽器的 cookie 不分埠，會跟 3000 的登入互相覆蓋）；用 `.env.prodtest` 裡 `SEED_ADMIN_PASSWORD` 的 admin 登入會被要求改密碼。試完**務必**清理（postgres／redis 映像顯示「still in use」是正常的，dev 堆疊還在用）：

```bash
docker compose -p qip-prodtest -f docker-compose.prod.yml --env-file .env.prodtest down -v --rmi all --remove-orphans
```

```bash
docker builder prune -f --filter until=24h
```

> 這條只清 24 小時前的建置快取；磁碟很緊、想立刻釋放就拿掉 `--filter until=24h`（會連 dev 的建置快取一起清，下次 build 慢一點而已）。

## 7A. AD 登入（正式機或院內網路的開發機；約 20 分鐘）

> 只在**要啟用 AD 登入**時做；AD 預設關閉，不啟用就跳過這一節。需要連得到院內 AD：正式機，或連上院內 Wi-Fi 的開發機。對象：品管中心主管，資訊室在場（提供 AD 設定與 AD 測試帳號）。
> **順序不能換**：7A-1 一定要在 AD 開啟**之前**做，否則開了之後系統沒有任何管理者能登入。AD 密碼**只由你親自輸入**，不要貼進聊天、文件或截圖；本節不記錄任何帳號密碼。
> 指令的寫法：開發機在專案目錄用 `docker compose exec -T api python manage.py …`；正式機用 `docker compose -p qip-prod exec api python manage.py …`。第一次要先 `docker compose build api`（新增了 `ldap3` 套件；build 前 `df -h /c` 剩 15 GB 以上）。設定檔：開發是 `backend/.env`，正式是 `.env.prod`，兩者都不入庫。

| 步驟 | 動作 | ✅ 預期 | 勾 |
|---|---|---|---|
| 7A-1 | **AD 還關著時**，admin 登入 → `/entry/admin` →「+ 新增使用者」→ 帳號填**你自己的員工編號**（要與 AD 帳號一致）、姓名、勾「管理員」→ 儲存 | 清單多一筆你的帳號。此時 AD 沒開，仍會彈出臨時密碼視窗：關掉即可，啟用 AD 後用不到 | ☐ |
| 7A-2 | 編輯設定檔：`LDAP_ENABLED=true`，並填 `LDAP_SERVER_IP`、`LDAP_BIND_USER`、`LDAP_BIND_PASS`、`LDAP_BASE_DN`（四個值由資訊室提供）；`LDAP_LOCAL_ONLY_ACCOUNTS` **先留空** | 存檔後 `git status` 看不到 `.env`／`.env.prod`（已列入 `.gitignore`） | ☐ |
| 7A-3 | 重啟 api：開發 `docker compose restart api`；正式 `docker compose -f docker-compose.prod.yml --env-file .env.prod up -d api`（`restart` 不會重讀正式的 `env_file`）。再看 log：`docker compose logs api` | 有一行 `[bootstrap] AD 驗證：啟用（…，本地帳號：無，所有帳號含管理者都必須通過 AD）`；主機與埠和你填的一致；log 裡**看不到**任何密碼。若寫「未啟用」，見 `docs/DEPLOYMENT.md` §8 | ☐ |
| 7A-4 | 執行 `ldap_check`（不帶參數） | 顯示服務帳號 bind 成功，結束碼 0。失敗：先找資訊室確認 389 連得通 | ☐ |
| 7A-5 | 執行 `ldap_check --user <AD 測試帳號的員編>` | 顯示找到、姓名、mail、部門（來自 AD）。不需要輸入密碼 | ☐ |
| 7A-6 | 執行 `ldap_check --audit` | 列出「系統裡啟用中、AD 查無」的帳號。**標 `[ADMIN]` 的管理者一個都不能在裡面**——你自己的帳號不該出現；`admin`、示範帳號（demo_*）出現是正常的（AD 沒有它們）。有 `[ADMIN]` 就回到 7A-1 修正員編 | ☐ |
| 7A-7 | 無痕視窗用**你自己的員編＋AD 密碼**登入 `/entry/login` | 登入成功、落在儀表板，**不會被要求改密碼**；登入頁副標是「請以員工編號與院內 AD 密碼登入」。F12 Console 執行 `fetch('/api/auth/me').then(r => r.json()).then(console.log)`，`auth_method` 是 `"ldap"`、`auth_source` 是 `"ldap"` | ☐ |
| 7A-8 | 用資訊室提供的 **AD 測試帳號**（系統裡還沒建）登入，密碼自己輸入 | 紅字「AD 驗證成功，但系統尚未開通此帳號，請洽品管中心」；不是「帳號或密碼錯誤」，也不是英文錯誤 | ☐ |
| 7A-9 | 用 7A-7 的管理者登入 → 帳號管理 →「+ 新增使用者」→ 帳號填 AD 測試帳號的員編、姓名、勾「填報者」。先看對話框，再儲存 | 對話框**沒有密碼欄**，改顯示「AD 帳號不需設定密碼…」的說明，帳號欄下提示須與 AD 帳號一致。儲存後**不彈**臨時密碼視窗；清單新那列帳號旁有 `AD` 小標，且**沒有**「重設密碼」鈕 | ☐ |
| 7A-10 | 再用 AD 測試帳號登入 | 登入成功、落在 `/entry`；不被要求改密碼；`/api/auth/me` 的 `auth_method` 為 `"ldap"` | ☐ |
| 7A-11 | 登出，用 AD 測試帳號輸入**錯誤的 AD 密碼 5 次** | 前 4 次「帳號或密碼錯誤」；第 5 次起「登入失敗次數過多，請 5 分鐘後再試」。鎖定中輸入正確的 AD 密碼也一樣被擋。**只用測試帳號做這步**：錯誤的密碼也會累計到 AD 自己的鎖定原則。解鎖：等 5 分鐘，或 `manage.py axes_reset_username <帳號>`（AD 帳號沒有「重設密碼」） | ☐ |
| 7A-12 | 用 `admin` 的**本地密碼**登入（此時清單為空） | 被擋：「帳號或密碼錯誤」。這是設計：純 AD，沒通過 AD 就進不來。（`admin` 被鎖也一樣等 5 分鐘） | ☐ |
| 7A-13 | 把 `LDAP_LOCAL_ONLY_ACCOUNTS=admin` 寫進設定檔，重啟 api（同 7A-3）；再用 `admin` 的本地密碼登入 | 狀態行的「本地帳號」列出 `admin`；`admin` 登入成功；7A-10 的 AD 測試帳號仍然走 AD 登入。**驗完依你的決定保留或清空**（保留 = AD 當機時還有緊急管理者；見 `docs/DEPLOYMENT.md` §4.1 第 2 步） | ☐ |
| 7A-14 | 以管理者重新看帳號管理頁（AD 帳號列與 `admin` 那列） | AD 帳號旁有 `AD` 小標、無「重設密碼」；`admin` 與其他本地帳號沒有 `AD` 小標，「重設密碼」仍在。（選做）AD 登入的 session 呼叫 `POST /api/auth/change-password` 會得到 403 `ldap_managed`「您的密碼由院內 AD 管理，如需變更請洽資訊室」，自動化測試已涵蓋 | ☐ |
| 7A-15 | 把 `LDAP_ENABLED` 改回 `false`（或刪掉該行），重啟 api | 狀態行是「AD 驗證：未啟用（僅本地密碼）」；`admin` 本地密碼可登入；AD 測試帳號用 AD 密碼**不能**登入；帳號管理頁沒有 `AD` 小標、新增對話框又出現密碼欄。一切回到 AD 啟用前的樣子（AD 登入時原本是「須改密碼」的帳號，本地密碼已作廢，需管理者重設） | ☐ |

> 7A-1 至 7A-14 是「啟用 AD」的驗收；7A-15 確認可退回。**在正式機上：做完 7A-1～7A-6（確認所有管理者都在 AD），再做 7A-7、7A-8、7A-12**，其餘寫入類的步驟（建測試帳號、5 次錯誤密碼）用測試帳號做，做完把測試帳號停用或刪除。啟用或退回時 `LDAP_LOCAL_ONLY_ACCOUNTS` 填什麼，以資訊室與品管中心事先決定的為準。
